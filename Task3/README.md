# Task 3. Данные, масштабирование и отказоустойчивость

Стратегия данных для целевой микросервисной архитектуры AdScale (Task1/TO-BE.md). Главный принцип - на пути ответа DSP-партнёру нет обращений к дисковым базам данных: hot path читает read-модели в Redis и локальном кеше, которые заполняются событиями из Kafka.

**Ключевые решения:**
- PostgreSQL для кампаний и финансов (транзакции, консистентность), ClickHouse для статистики и аналитики (поток записи, агрегации), Redis для read-моделей hot path.
- Синхронная репликация и автоматический failover для Campaign и Financial, шардирование событий в ClickHouse и read-моделей в Redis, CQRS для hot path.
- Kafka: топики по доменам, Avro со Schema Registry, независимые группы потребителей, DLQ, компактируемые топики для прогрева кеша.
- RPO 0 для денег и изменений кампаний, резервные копии с восстановлением на момент времени и ежемесячной проверкой восстановления.
