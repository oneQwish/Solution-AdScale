# Кеширование

## Принцип
Сервисы на пути ответа партнёру (Ad Server, Bidding, Delivery) никогда не ходят в базы данных. Всё нужное им лежит в кеше заранее: Cache Updater заполняет его по событиям из Kafka. Если данных в кеше нет, кампания просто не участвует в аукционе. Так время ответа не зависит от баз, а падение базы не останавливает аукцион.

Кеш двухуровневый:
- **локальный** - копия данных в памяти каждого инстанса сервиса. Самый быстрый, обновляется каждые несколько секунд;
- **Redis** - общий кеш для всех инстансов, в каждом регионе рядом с сервисами hot path.

## Где размещён Redis

Два отдельных кластера Redis:
- **основной** - ставки, бюджеты, таргетинг, правила партнёров, шаблоны баннеров. Эти данные нельзя выбрасывать при нехватке памяти, иначе изменится результат аукциона, поэтому при заполнении памяти поднимается алерт;
- **сегменты пользователей** - большой объём, при нехватке памяти выбрасываются давно не использованные записи. Потеря некритична: пользователь получит менее точную рекламу.

Redis не является источником истины: любые данные в нём можно восстановить из Kafka или баз сервисов.

## Что кешировать

| Данные | Кто читает | Сколько живут в кеше | Как обновляются |
| ------ | ---------- | -------------------- | --------------- |
| Ставки и параметры кампаний | Bidding | Redis - сутки, локально - 5 с | По событию изменения кампании |
| Таргетинг кампаний | Ad Server | Redis - сутки, локально - 5 с | По событию изменения кампании |
| Остатки бюджетов | Bidding | Redis - без срока, локально - 1 с | По событию Financial: при изменении и раз в 10 с. Если не обновлялись дольше 30 с - не используются |
| Сегменты пользователей | Ad Server | 7 дней, срок продлевается при обращении | При обновлении профиля пользователя |
| Шаблоны баннеров | Delivery | Redis - сутки, локально - час | По событию изменения креатива |
| Правила партнёров | Bidding, Ad Server | 10 минут | При изменении настроек партнёра |
| Готовые отчёты кабинета | Analytics | 5 минут | Только по истечении срока |

**Не кешируем** балансы для списаний и счетов: источник истины только финансовая база. Кеш бюджета нужен лишь для решения «ставить или нет».

## Инвалидация

- Основной способ - события: изменили кампанию или бюджет, событие пришло в Kafka, Cache Updater перезаписал данные в Redis.
- Срок жизни в Redis (сутки) - страховка на случай потерянного события, чтобы устаревшая запись не жила вечно.
- У каждой записи есть номер версии: если событие пришло с опозданием, старые данные не перезапишут новые.
- Если Redis недоступен, локальная копия продолжает работать до 30 секунд (Task2/reliability.md).

## Прогрев кеша

| Ситуация | Что делаем |
| -------- | ---------- |
| Пустой Redis (первый запуск, авария) | Cache Updater перечитывает из Kafka последнее состояние всех кампаний и бюджетов - Kafka хранит его постоянно. Запасной вариант - выгрузка из реплики базы Campaign |
| Запуск нового инстанса сервиса | Инстанс не получает трафик, пока не загрузит локальную копию активных кампаний и бюджетов из Redis (секунды) |
| Запуск второго региона | Redis региона наполняется до того, как туда направляют партнёров |
| Новая кампания | Попадает в кеш через секунды после сохранения, до начала показов |

## Мониторинг
Доля запросов, найденных в кеше, время ответа Redis, отставание Cache Updater, возраст самых старых данных о бюджетах, заполнение памяти (алерт при 75%).
