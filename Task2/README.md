# Task 2. Проектирование RTB и интеграции с DSP

Сервис ставок выделяется из монолита первым (Task1/adr/ADR-001.md). Цель - ответ DSP-партнёру не более 80 мс при 18 000 RPS через 3 месяца и 50 000 RPS через год.

**Ключевые решения:**
- Bidding Service stateless, без синхронных зависимостей: всё для аукциона читается из Redis и локального кеша.
- Внутри hot path - gRPC с deadline, снаружи - OpenRTB 2.6 поверх HTTPS, события - Kafka.
- Бюджет 80 мс разложен по участкам пути, у каждого вызова свой таймаут.
- API Gateway - Kong: аутентификация партнёра, rate limiting, health checks, метрики задержки по партнёру.
- При проблемах зависимостей партнёр получает «нет ставки» (HTTP 204) в срок. Финансовые операции идемпотентны по ключу показа.
